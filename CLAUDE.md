# CLAUDE.md: project context for Claude Code

This file carries the full project brief and the decisions made so far, so work can continue in any Claude Code session (local or cloud) without re-explaining. Keep it updated when significant decisions are made.

## The brief (from the project owner)
Operator Board is a Virtual Production, operator-friendly extension to Unreal Engine **Switchboard**: an easily navigable UI for controlling UE virtual production.

1. **Primary:** at the push of a button, **freeze** and/or **blackout** the LED wall, or show a **test pattern** from the LED processor. The user selects their LED processor type and, if it is networked and configured, commands go straight to it. It must support all major / common LED processors and connect **the same way Bitfocus Companion does** (host/IP + port per module).
2. All standard Switchboard functionality on easy-to-read displays: connect to and start UE instances (editor, nDisplay nodes…); start, name and monitor a **multi-user server** (show the connected count); start and stop **groups** of instances.
3. Integration with **file sync / revision** setups such as FreeFileSync, and **analytics** for live instances (raw data and graphs). These go on **separate pages** from the main display.
4. Load and swap **levels** within a project, and if possible between **projects**.
5. A list of **instance-editable objects** controllable remotely.
6. A configuration page for **control surfaces (Stream Deck)** covering all standard operations (load or swap levels, start or stop multi-user, freeze, blackout…). It needs a **default config**, user customisation, and **save/load to an external file** for use on another machine.
7. An easy UI for creating, controlling and saving **takes**, as in Switchboard.
8. **DLSS** settings control when the project uses the DLSS plugin.
9. Toggle **sub-levels** (often used for lighting setups) and move between **saved camera locations**.
10. Keep a list of **potential future features**, but NOT in the README. The **README lists only currently available features and the supported UE versions (5.2 → 5.8)**.
11. Hosted on GitHub as `JamesWardVP/Operator-Board`.

## Building and releasing (keep to this)
- **Local testing:** close any running Operator Board first (Windows locks `dist/`), then `python packaging/build.py --hidapi`. That rebuilds `dist/OperatorBoard/` (run `OperatorBoard.exe` from there to test) and, for the current version, `dist/OperatorBoard-<version>-win64.zip` and `dist/OperatorBoard-Setup-<version>.exe` (the installer is built whenever Inno Setup 6 is installed; older packages are removed). Always build into `dist/`, never side folders.
- **Release:** (1) `python packaging/bump_version.py X.Y.Z` (updates `operator_board/__init__.py`, README, this file); (2) run the tests, commit and push to `Development`; (3) PR `Development` -> `main`; **the owner merges it** (merging from a session is blocked by the permission check); (4) tag `vX.Y.Z` on `main` and push the tag; (5) GitHub Actions builds and attaches the installer and zip to the release (it fails if the tag does not match the version); (6) add "What's new" notes above the automatic install text.

## Key decisions & research findings
- **Single ActionRegistry** (`context.py`): the UI, Stream Deck, Companion HTTP API (`/api/action/<id>`) and hotkeys all invoke the same actions. Add new features as actions.
- **Listener protocol** mirrors Switchboard's `message_protocol.py`: null-terminated JSON, `start` / `kill` / `keepalive` / `get sync status`, program name `"unreal"`. **UE 5.4+ listeners use QUIC over UDP 2980 with a password** (TCP 2980 is closed); 5.2-5.3 use TCP. Checked against Switchboard 5.2/5.6/5.8 sources and a real 5.8 listener (handshake, `authenticate` reply, wrong-password rejection). Replies echo ids as FGuid strings, so compare ids with `protocol.same_id`. Program messages nest details under `process` (`uuid`, `pid`, `name`, `caller`) and every connection hears every program, so `caller` must be the device name and messages are filtered by it (`protocol.program_info`). The keepalive command is `"keep alive"`. The multi-user **server** may only get `-CONCERTSESSION` together with `-CONCERTPROJECT=<uproject name>` (alone it creates a project-less session that refuses every client); with both, editors join it, and an existing session of that name is reused (verified on a real 5.8 server). Sessions are recovered after a forced shutdown. nDisplay nodes need the cluster JSON extracted from the config asset and written to the node with `send file` (`devices/ndisplay.py`). Passwords are shared with Switchboard through Windows Credential Manager (`Switchboard_<host>`), verified by reading an entry written by Operator Board with Switchboard's own code. See docs/ARCHITECTURE.md.
- **Remote Control security switches** (`URemoteControlSettings`, all off by default): `bEnableRemotePythonExecution` (5.2+), `bAllowConsoleCommandRemoteExecution` (5.6+), `bAllowAnyRemoteFunctionCall` (5.8 allowlist). Without them Take Recorder / levels / cameras fail with "Object Default__PythonScriptLibrary cannot be accessed remotely". Operator Board passes `-ini:RemoteControl:[/Script/RemoteControlCommon.RemoteControlSettings]:...=True` when it launches an instance (`launcher.REMOTE_CONTROL_UNLOCK`, setting `remote_control.allow_remote_features`); verified on a real 5.8 editor (blocked without, allowed with). Take Recorder in 5.8: a just-opened panel has no take metadata until the editor ticks, so `take_recorder_start` returns `retry` and `TakeManager` calls again; verified up to (not including) `start_recording`. Take Recorder records only the sources in its panel; with none, `start_recording` raises "There are no currently enabled or valid sources" (Operator Board explains it; optional `takes.take_preset` asset is applied with `setup_for_recording_take_preset` first). Slate/take changes are pushed to an open panel by one background sender that always sends the latest values. `run_python` raises on a `{'error': ...}` result. Empty take: `takes.auto_add_camera` adds a source with `TakeRecorderActorSource.add_source_for_actor` (static, Python-callable in 5.8): `take_camera` label, else the ICVFX camera's `camera_settings.external_camera_actor`, else the nDisplay root holding an ICVFX camera, else a CineCameraActor, else the nDisplay root; verified on the real nDisplayTest level (no ICVFX camera there, so it picks CineCameraActor1). Timecode/genlock (`remote/timing.py`): `TimingMonitor` runs `scripts.editor_timing` on the primary editor every second (`unreal.TimeManagementLibrary.get_timecode()`, ~20 ms; zeros or no reply = "No data"; the UI ticks it on between polls). The engine's timecode provider and the custom time step's lock state are not reachable from Python in 5.8, so genlock comes from the listener sync status `syncTopos` (`SYNC_TOPOS` flag, read like Switchboard's nDisplay monitor: every `syncGpus[].bIsSynced`), else the editor's custom time step name is shown as a setting, not proof. Multi-user + Take Recorder: the Concert sandbox copy of a recorded subsequence (`Intermediate/Concert/MultiUser/<id>/<id>/Sandbox/Sandbox/<Project>/Content/<take path>`) failed at 320 characters with Windows long paths off ("ConcertSyncSessionDatabase: Unable to open a file for writing"); `take_recorder_start` estimates that length in the editor (exact for the reported case) and Record reports a warning. Countdown: `take_recorder_start` returns `TakeRecorderUserSettings.settings.countdown_seconds` (default 3); `TakeManager.phase` is "countdown" until `take_recorder_status` (`get_active_recorder().get_state()`, `TakeRecorderState.STARTED`; `get_countdown_seconds()` is the live remainder) says recording; stop during the countdown = `cancel_recording`, nothing logged. Save: `panel.get_last_recorded_level_sequence()` after stop (remembered as `TakeRecord.sequence`), `EditorAssetLibrary.save_asset(..., only_if_is_dirty=True)` for the sequence and its `_Subscenes`, then in a session `unreal.MultiUserClientStatics.persist_specified_packages` (local disk only, nothing broadcast); verified the 5.8 Python names and that a clean asset is not rewritten. A take that failed the long-path copy stays in the session, so every client that joins later shows the same Concert error until long paths are on or the session is cleaned. Session numbering (`multiuser.auto_increment_session`, default on): `MultiUserServer.stop()` moves to `next_session_name` (VP_Session -> VP_Session_2, keeps zero padding); `start()` waits (up to 20 s) for the server's "Multi-User Editing Server Initialized" line, collecting "Live session 'X' (id) was recovered." lines printed before it (verified on a real 5.8 server restarted after a forced stop), and if the session name is among them moves to the next free name with a warning (event `multiuser.session_renamed`, config saved). Devices build their command line after the auto-start hook, so they join the new name. Multi-user flow: `start(interactive=True)` (the UI button) starts the server without a session and, on a name clash, sets `clash` + publishes `multiuser.session_clash` (the Operate page asks: new session or keep); `resolve_clash`; `start_session()` restarts the server with `-CONCERTSESSION/-CONCERTPROJECT` (no `-CONCERTCLEAN`). `auto_start_session` (default off) does that straight after start when there is no clash. `session_live` comes from start_session or a client creating/joining the session after the server is ready (a session recovered at start-up does not count). Button: purple START SERVER, orange START SESSION, pale green STOP SERVER (live). Cameras: listed by class in Python (`CameraActor`, `DisplayClusterRootActor`, so Blueprint nDisplay configs appear); capture/recall on the editor use Python (`get_actor_transform`/`set_actor_transform` in a ScopedEditorTransaction), because 5.8 blocks Remote Control calls like K2_GetActorLocation unless the editor was started with the unlock switch; names get `_2`, `_3`. Save take looks the take up by `<slate>_<take>` under Take Recorder's save folder when the panel forgot it, with a 180 s timeout. Editor ready (`remote/editor_watch.py`): every 3 s (5 s once ready) a short-timeout Python check (editor world exists and `AssetRegistry.is_loading_assets()` is false) publishes `editor.ready` / `editor.level_changed` / `editor.lost`; the Cameras & Levels and Remote Objects pages then pull their lists quietly (`BasePage.background(quiet=True)`) and show 'No ... found' placeholders. Light/camera quick controls (`scripts.actor_quick_controls` / `set_actor_quick_control`, verified on real RectLights and a CineCameraActor in 5.8): light colour is sRGB from the picker, converted to linear before `set_light_color(..., True)`; values are locked when the actor has a LiveLinkComponentController, a LensComponent or DMX component. Control surfaces: several at once (`surfaces/manager.py` SurfaceManager, one SurfaceController per surface; `ctx.surface` = the first). Each SurfaceLayout has `id`, `name` (unique), `enabled`, `device` (Stream Deck serial / MIDI input name; empty = next free matching device). Stored as dicts in `surfaces.devices` (a machine setting, so the same on every stage); the old `layout_path` / `midi_*` become the first surface once (`devices_migrated`). Export/import file: `{"format": "operator-board-surfaces", "surfaces": [...]}` (an old single-layout file also imports). Stream Decks: `StreamDeckBackend.scan()` opens new decks and drops unplugged ones, `assign()` matches serial first then key count; `MainWindow.nativeEvent` catches WM_DEVICECHANGE and calls `ctx.refresh_surface_devices(only_if_changed=True)` after 1.5 s (MIDI reopened only when the input list changed). Web panel `?surface=<id>`, OSC `/operator/surface/<n|name|id>/...`; without one they use the first web (else Custom) / OSC (else Custom) surface. New surfaces = default buttons re-flowed per page (`layout.fit_to_model`/`reflow`), last key of every page Next page when there is more than one page; `ensure_page_navigation` runs on new pages and size changes only, so an operator can clear it. Key text: `text_color`, `font_size` (px on a 72-px key, scaled; 0 = auto), `font_weight`, `word_wrap`; `surfaces/render.fit_label` is shared by the Stream Deck (Pillow, Segoe UI by weight) and the on-screen deck, and shrinks before breaking a word. LED processor types: built-ins are never edited; `ProfileRegistry.save_custom` writes `<id>_custom.json` (`based_on`, name "(custom)") to `~/.operator_board/led_profiles`, edited commands get confidence "user"; editing a custom type saves in place; `delete_custom` returns `based_on`. LED modes: each processor has one `mode` (normal, frozen, blackout, pattern, locate; `LEDProcessor.mode`, precedence blackout > pattern > frozen > locate); locate needs `locate_on`/`locate_off` commands (Simulator only so far). `LEDManager.set_mode(target, mode, pattern)` takes a processor, an LED group (`AppConfig.led_groups`, `LEDGroupConfig`) or "all", clears the other modes first, and returns to normal when they are all already in that mode; action `led.set_mode`. `ui/led_status.status_groups` groups processors by state for `WallStatusBar.show_processors` (one bar "ALL PROCESSORS ...", or one part per state). `ui/led_controls.ModeButtons` is the five lit buttons (row on LED Processor Setup and its Advanced panel, column on the LED Processors page). Change log (`core/changelog.py`): `ctx.changes` records every `action.invoked` except `AppContext.NOT_LOGGED` (surface pages, LED wall/group states `led.*` apart from `led.brightness`, `devices.*`, `group.*`) (now carrying params, label, category) plus Remote Objects / sub-level / preset changes with slate, take, timecode, project, level, value and previous value, in `~/.operator_board/change_log.jsonl`; CSV export, and `ctx.production_export` writes an .xlsx (openpyxl) with Summary, Change log, Takes, Camera positions, LED processors and Unreal instances sheets. Remote Objects Undo re-applies a record's previous value through `ctx.apply_setting(kind, ref, value)` (kind quick / property / preset); `ctx.changed_settings()` is the latest value of each setting changed this run. Saved settings presets (`core/presets.py`, `AppConfig.setting_presets`): items of ITEM_TYPES applied in ITEM_ORDER by `steps()`, each raising `PresetProblem` (missing data, failure or a failed check) so the Saved Settings page asks retry / skip / cancel; the level step waits until the editor has the level open. No editor running: `TargetResolver.editor_or_nodes(fn, all_nodes)` runs on the primary editor, else (only when it is not set up or unreachable) on the first nDisplay node that answers, or every node for changes; `ObjectService` reads and quick-control changes use it (verified on a real -game node: actors, quick controls, describe, values, Set), and quick-control changes skip the editor transaction in a game world. Archive last session (`multiuser.archive_last_session`, verified on a real 5.8 server): Concert's `UConcertServerConfig.bAutoArchiveOnReboot` (`-ini:Engine:[/Script/ConcertServer.ConcertServerConfig]:bAutoArchiveOnReboot=True`, `launcher.ARCHIVE_ON_START`) archives the live sessions left by a forced stop as the server starts ("Live session 'X' (id) was archived on reboot."). `MultiUserServer._archive_previous` restarts the server with it once a new session name is settled and older sessions exist (after start without a clash, or "new session" at the clash prompt); keeping the existing session archives nothing. Listener prompt: an OSError on connect publishes `device.listener_unreachable` (with `local` for this PC); `MainWindow._offer_listener` asks once (not again for 2 minutes after an answer), `AppContext.start_local_listener` starts `<engine>/Binaries/Win64/SwitchboardListener.exe` detached unless one is running (tasklist), then `reconnect_local_devices` retries for 20 s. Remote Control ports (verified on 5.8): UE ignores `-RCWebControlPort`; the HTTP port is the `RemoteControlHttpServerPort` setting (WebSocket `RemoteControlWebSocketServerPort`, launcher uses port + 10) and the HTTP server listens on 127.0.0.1 unless `-ini:Engine:[HTTPServer.Listeners]:DefaultBindAddress=0.0.0.0` (added for devices not on this PC). `devices.manager.unique_rc_ports` gives every device on one PC its own port on reload (event `device.rc_port_changed`). Before this an editor and a node on one PC both used 30010, so editor requests reached the node ("'NoneType' object has no attribute 'get_all_level_actors'") and the editor-ready check never passed. Python runs on -game nodes too (no editor subsystem): `scripts.LEVEL_ACTORS` uses the editor's actors, else the game world with the most actors; cameras recall/capture/list in the editor, else on every nDisplay node. `scripts._lit` writes Python literals (json.dumps gave `true`, which broke the bool light toggles). `editor.*` events go to every page, not only the visible one. Light units: `set_intensity_units` does not convert, so `set_actor_quick_control` mirrors the engine's ComputeLightBrightness/SetLightBrightness (point/spot/rect, Nits, EV; verified 3 cd = 9.42 lm = EV 4.58 on a rect light). Actor property values: one `/remote/object/property` READ_ACCESS without a property name returns them all. Button actions `osc.send` (`surfaces/osc_send.py`, Companion-style argument types) and `macro.run` (`AppContext.run_steps`: `{"action", "params"}` / `{"delay": ms}`, failures reported, the rest run, no nesting); their editors are `ui/action_editors.py`. Taskbar: `SetCurrentProcessExplicitAppUserModelID("JamesWardVP.OperatorBoard")`, same ID on the installer shortcuts. `layout.MODELS` lists Stream Decks, web panel sizes, OSC, MIDI (APC mini, Launchpad programmer mode, 16-pad) and Custom; `MIDI_MAPS` number pads from the bottom-left (untested on real MIDI hardware). The web panel is `/panel` on the HTTP API (`surfaces/web_panel.py`, polls `/api/surface`, presses `/api/surface/press/<n>`; 'Allow phones and tablets' binds 0.0.0.0 and creates a token). OSC: `surfaces/osc.py`, pure-Python UDP, /operator/... MIDI: `surfaces/midi.py` with optional mido + python-rtmidi (bundled when installed). LED wall: a background check (`AppContext._led_monitor`) runs at start-up and every 15 s while any processor is not confirmed online; the Operate page overlays the LED card with hazard tape (`widgets.HazardOverlay`) when none is set up or all are unreachable.
- **Remote Control** (port 30010) is used for everything inside Unreal. Editor-only operations run Python through `ExecutePythonCommandEx` and return JSON via an `OPB_RESULT:` print marker. These need the Python Editor Script Plugin.
- **LED protocols** (researched against Bitfocus Companion module sources):
  - NovaStar: binary TCP 5200 (VX Pro: 15200). Checksum = sum(bytes[2:]) + 0x5555, as LE uint16. Display-mode frames come from source. The MCTRL "Normal" frame was corrected to `…00 01 00 02 01 00 00` (matches published checksum D6 59). Test-pattern frames use byte 3 = 00 (Red verified).
  - Brompton Tessera: HTTP `GET /api/override/{freeze|blackout|test-pattern}/enabled?set=…` and `/api/output/global-colour/brightness?set=` (nits). Paths come from source; the `true`/`false` values are assumed.
  - Megapixel HELIOS: `PATCH /api/v1/public` (from the PepperDash docs). The JSON bodies are partial or assumed.
  - Every command has a `confidence` field that the UI shows. **Nothing has been tested on real hardware yet.**
- Multi-user client counting parses server logs with configurable regexes. The exact Concert log wording has not been verified against a real server.
- DLSS controls are data-driven in `remote/dlss.json` (DLSSLibrary.SetDLSSMode, StreamlineLibraryDLSSG.SetDLSSGMode, plus cvars).
- **Switchboard configs** (`core/switchboard_config.py`, `core/stage.py`, Stage page): Operator Board opens/creates/saves the real Switchboard config files in Switchboard's own folder (`<Engine>/Plugins/VirtualProduction/Switchboard/Source/Switchboard/configs`, `SWITCHBOARD_CONFIG_DIR` from 5.6). Format checked against the 5.2, 5.6 and 5.8 sources and real 5.8 configs. Operator Board-only settings go in a `<name>.opboard` sidecar (never `.json`: Switchboard rglobs `*.json`). Only mapped keys are merged, so real configs round-trip unchanged. A config created by Operator Board was loaded by Switchboard 5.8's own `Config` + `DeviceManager` successfully; Switchboard dropped the per-device listener `port` on save (it is per device type), so the sidecar keeps it.

## Not yet verified (top priorities for real-world testing)
1. LED commands marked partial or assumed, on real Brompton, HELIOS and NovaStar hardware.
2. Starting/stopping Unreal through a real listener after a successful password login (5.8 handshake and login replies are verified; a full start was only tested against the fake QUIC listener), and the TCP protocol against real 5.2/5.3 listeners.
3. Python snippets in `remote/scripts.py` inside a real editor: the sub-level visibility getter, and an actual Take Recorder recording (5.8 panel/metadata calls are verified, `start_recording` itself is not).
4. Concert log patterns for the multi-user client count.
5. Opening an Operator Board-created config in the Switchboard UI itself on 5.2–5.7 (5.8 was checked through Switchboard's own loader, not by clicking through its window).

## Conventions
- Keep Python 3.9 compatible: no `match`, no `X | Y` type unions at runtime, no walrus.
- Core packages must not import Qt; only `ui/` and `qt.py` do.
- The README lists shipped features only; ideas go in `docs/ROADMAP.md`.
- Do not put model identifiers in commits or docs.
